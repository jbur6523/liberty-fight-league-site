## Data and voting rules

- Cards read the current event's **active** `superfight_matches`, joined to their configured competitors. Multi-fighter gauntlets appear as one **Group Pick** card: fighter A beats every configured opponent, or any opponent beats fighter A. All B/C/D names, academies and photos come from those competitor records. No opponents are inferred and no separate fighter list is maintained.
- Migration `20260927221159_fan_group_picks.sql` adds a service-only v2 snapshot and extends the existing voting function. Group outcomes use the immutable A ID for a sweep and B ID as the opponent-group choice key (never a claim of an individual B win); C/D IDs are rejected as standalone votes. Existing uniqueness, rate limits, closure, row locks and RLS remain in effect. The old snapshot still omits groups so an older frontend does not invent a two-fighter pairing. Group labels carry through summaries, saved parlays, sharing and normal/parlay ticket downloads. No additional environment variables or storage setup are required.
- The existing match trigger makes participants immutable. An opponent change requires unmatching and a new match ID, so old votes cannot follow a fighter into a new pairing. Name, academy and image edits keep votes intact.
- Only competitor ID, first name plus last initial, academy, photo URL, percentages, per-fighter real pick counts, matchup ID, bout type, agreed weight, real total, calculated fan lines/highlights and the current browser's selected fighter ID leave the public API. Full records, contact fields, cookie identity and IP signals are excluded.
- Each browser receives a random, signed, HttpOnly, SameSite=Lax cookie lasting one year; HTTPS deployments add Secure. Only a keyed hash of its identity is stored with votes. POST requires a valid previously issued cookie. There is no localStorage identity and no Supabase Auth account per visitor.
- `(match_id, voter_hash)` is the database primary key. The service-only voting function atomically upserts the pick, so retries/concurrent submissions and changes count as one vote. Event and match row locks coordinate votes with closing voting, switching the current event and unmatching.
- Persistent database rate limits allow 40 vote submissions per browser per minute, plus 1,200 per network per minute. Shared Wi-Fi visitors get separate votes. IPs are HMAC-hashed, never stored raw; Vercel's trusted IP header is used in production. Expired rate buckets are removed opportunistically after a day. This is abuse resistance for casual polling, not guaranteed person-level uniqueness.
- Percentage A is `round((A + 2) / (A + B + 4) * 100)`, clamped to 1–99; B is its complement. The total is `A + B`. Baselines are never inserted into the vote table.
- `src/superfight/fan-lines.js` converts displayed percentages into implied-probability moneylines, rounding to the nearest 5 (50/50 → PK/PK; 60/40 → -150/+150). Complementary integer shares avoid opposite-side floating-point rounding differences. These community lines are not actual win probabilities.
- The opening line is the immutable **PK** rule: every pairing begins with equal baseline support. It is never recomputed from current votes. This version has no configurable unequal starting lines, so no per-match opening snapshot or new migration is needed. A future unequal-opening feature must persist its own opening configuration before changing this rule.
- Movement is the signed change in displayed percentage points from the 50% opening, not recent momentum. Most Picked ranks real per-fighter picks in a current matchup; Biggest Favorite ranks support above 50%; Closest Line minimizes the support gap; Biggest Mover ranks positive change since opening. The latter two individual leaders may be the same because every market opens evenly. Stable matchup/fighter IDs break ties. No-vote matchups have no individual highlight leader.
- Cards refresh after successful votes, when returning to the tab, and every 30 seconds while visible. The public API is uncached. A failed save preserves the last confirmed selection and displays a per-card error.
- Image replacement uses a fresh object path to avoid stale CDN images and compares the previous path before changing the competitor record. A confirmed concurrent loser removes only its newly uploaded object. An uncertain database write retains the new object to avoid breaking a potentially committed reference; an orphan can require later cleanup. Removal clears the competitor reference and removes the old object; already cached copies may remain until their cache expires.

## Verification

### Fan Parlay

Normal Fan Picks have their own **Download My Picks** control below the matchup board. It exports confirmed selections from the voter-specific server snapshot, with each fighter's current odds and a capture timestamp. One saved vote is sufficient. It does not use parlay selections or combined odds, and downloading never casts votes. An image link is available if the browser does not start the PNG download automatically.

The public board and admin Matched list use the published RWI 3 card order in `src/superfight/board-order.js`, keyed by verified event and matchup IDs. Admin rows show the published match number. Unknown new matchups remain visible after scheduled cards; other events retain their supplied order. The main event retains its label but appears at match 30. This changes display order only. The main site navigation links to `/odds` as **Live Odds**.

The small secondary **Build a Fan Parlay** button below the ticket CTA enables a separate, client-only selection mode. Each matchup contributes at most one fighter; tapping a selected fighter removes that leg. These actions never submit the voting endpoint. Picks automatically save in localStorage by event, storing only matchup and fighter IDs. **Back to Fan Picks** restores normal voting and retains the draft. Returning visitors see **View My Parlay**; the slip stays hidden until requested. No account or additional identifier is used. Saved picks are specific to this browser and disappear if its site data is cleared. Storage failures display an explanation and do not prevent building, downloading or sharing.

The slip is initially hidden and appears compactly only after two selections in builder mode. **Lock In Parlay** opens a scrollable review dialog with **Download Ticket**, **Share Parlay**, **Edit Picks** and **Clear Parlay**. Close or Escape dismisses the review without clearing picks. The page reserves space for the compact slip. Downloads generate a PNG in the browser with the official logo, picks, combined fan odds and a timestamp; an image link supports browsers that do not start downloads automatically. Saved drafts follow live lines while downloaded images capture a moment in time. Native text sharing has clipboard and selectable-text fallbacks. No wagering, monetary stakes, payouts, or prizes are implemented.

`src/superfight/parlay.js` combines implied probabilities from the displayed moneylines, treating PK as 50%, and rounds the resulting American line to a whole number. Very large values use scientific notation; logarithms avoid overflow. This is a community-derived combination, not a claim of actual independent win probabilities. Existing 30-second snapshot refreshes update draft names and odds; removed matchups/fighters are pruned and an event change clears all legs. Closed voting disables Fan Pick submissions but leaves the separate entertainment draft usable.

No new database migration, dependency, storage bucket, environment variable or setup is required. Parlay tests cover math (including extreme values), selection isolation, replacements/removal, refreshed lines, event changes, all share fallbacks, automatic save/restore/clear, malformed or blocked storage, event isolation, changed pairings and safe PNG ticket rendering.

Run `npm run check` for module loading, frontend syntax checks and all tests. This static repository has no separate bundler/build command; Vercel serves the static files and packages the `api/` functions. No framework migration was introduced.

In **Matched**, choose a competitor in **Winner**, then click **Save result**. Choose **No result yet** and save to clear an incorrect result. Results are stored separately from confirmation and flyer status; the match remains visible. Normal and gauntlet matches accept only their configured participants. For a gauntlet, an opponent win highlights the opponent-group outcome while naming the actual winning competitor. Selecting the anchor means the anchor won the overall gauntlet.

Live Odds shows a FINAL banner and highlights the winning side on its next successful refresh (normally within 30 seconds while visible). Result publication closes voting for that match inside the existing row-locked voting function; existing votes and percentages remain intact. Clearing a result reopens that match when event voting is open. Existing parlay drafts are preserved, but completed matches cannot be added or changed through card selection. No automatic parlay settlement is introduced.

The existing promoter authentication and match RLS protect result writes. A database constraint rejects a winner outside the immutable match participants. Public snapshots expose only the winning participant ID alongside already-public abbreviated competitor information.

## Official weigh-ins

In **Matched**, enter each fighter's **Official weight (lb)** and select **Save weight**. Decimal pounds are supported; clear the field and save to remove an entry. Each fighter, including additional gauntlet participants, has an independent saved weight. The weight belongs to the event's competitor record, so it survives rematching without changing the agreed bout weight. Weigh-ins are admin-only and are excluded from the Live Odds projection.

On phones, matches display as stacked cards with weigh-in controls beside each fighter, followed by bout information and the winner selector. **Fighter details** contains photo and contact controls; **Match actions** contains bout editing, flyer status, and unmatching.
